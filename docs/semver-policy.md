# Политика совместимости — справка

Политика классифицирует изменения публичного пакета. Текущую версию и точки
входа содержит [генерируемая справка](package.md); наличие версии в исходниках
не подтверждает её публикацию в npm.

## Классы изменений

Правила ниже различают период до первого production-потребителя и последующее
использование. Сам факт существования исходников не устанавливает этот переход.
Наличие потребителя подтверждается его интеграцией, а не номером текущей задачи.

| Изменение | До первого production-потребителя | После |
|---|---|---|
| Новое имя иконки | minor | minor |
| Удаление или переименование имени | minor с записью об устаревании | major |
| Изменение байтов SVG с сохранением смысла | patch | patch |
| Изменение смысла или узнаваемости формы | minor | major |
| Новая ось у варианта | minor | minor |
| Удаление оси | minor | major |
| Расширение union-типа | minor | major: может сломать исчерпывающий разбор потребителя |
| Новый необязательный ключ объекта | minor | minor |
| Изменение семантики существующего ключа | Новое имя ключа | Новое имя ключа |
| Изменение внутреннего формата `topologySignature` | Непрозрачное значение, разрешено только сравнение на равенство | patch при сохранении непрозрачного контракта |
| Приёмка модели `candidate → accepted` | minor | minor |
| Изменение порогов качества | minor с обоснованием | minor с обоснованием |
| Изменение траектории или easing существующего gesture ID | Новый ID | Новый ID |
| Новая версия `proposalVersion` | Прежняя версия принимается либо получает явный отказ с кодом | То же правило |

Приёмка модели может менять байты геометрии, возвращаемой default-режимом:
авторский источник заменяется принятой моделью. Это объявленное поведение.
Потребителю, сохраняющему снимки SVG/path, следует фиксировать minor-версию.

Устаревающее имя сохраняется как минимум один minor с пометкой в каталоге.
Удаление после появления production-потребителя относится к major.

## Явно нестабильные поверхности

Motion/morph-контракты, включая `MotionGestureContract`, `sampleMotionGesture`,
состояния возможностей и варианты tracks, не объявлены стабильными.
До явной стабилизации расширение их union-типов в линии 0.x допускается в minor;
потребитель обрабатывает неизвестный вариант, а не предполагает закрытое множество.
Стабилизация требует отдельного решения и записи в политике совместимости.

`iconDesignContract.agent` с репозиторными командами также не является стабильным
потребительским интерфейсом. Команды разработки принадлежат checkout, а не
установленному пакету. Их присутствие не создаёт обещания пригодности вне репозитория.

## Проверка изменения

Сравнение [снимка runtime-экспортов](../release/export-surface.json) с построенным
пакетом обнаруживает изменение имён экспортов. Снимок нельзя обновлять только
ради зелёного результата: diff должен соответствовать объявленному изменению.

Проверка пакета дополнительно проверяет точки входа и разрешимость деклараций
типов в потребителе. Эти проверки не присваивают класс SemVer автоматически
и не доказывают поведенческую совместимость по одному списку имён.
Класс изменения, смысл существующих полей, визуальная семантика и границы
экспериментальных поверхностей проверяются в ревью вместе с тестами продукта.

Процедура выпуска находится в [сборке и релизе](build-release.md).
