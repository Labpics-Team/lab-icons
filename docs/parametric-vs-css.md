# Параметрическая модель и CSS — решение

Статус: принято.

## Разделение ответственности

Перемещение, вращение, масштабирование и прозрачность готового SVG потребитель
может задавать средствами платформы. Библиотека не вводит собственный
исполнитель только для обёртки этих операций.

Параметрическая модель нужна для изменения конструкции с сохранением её
контракта: веса заполненной формы, отрицательного пространства, объявленных
скруглений и оптических пропорций. Масштабирование всего изображения не
обеспечивает эти свойства автоматически.

## Части и анимация

CSS и WAAPI могут управлять отдельно размеченными частями SVG.
Назначение анатомии не в запрете такого пути, а в стабильном контракте частей:
их идентичности, смысловой роли, опорных точках, допустимой траектории и
условиях совместимости. Эти сведения нельзя вывести из единого произвольного
контура только по факту его наличия.

Смысловой жест описывает изменение конкретных частей. Целоглифовый fade или
rotate не выдаётся за доказанный жест частей.

## Не выбранные замены

Хранение отдельного SVG для каждой комбинации непрерывных осей создаёт
множество независимо поддерживаемых форм. Оно не заменяет общий закон
построения и проверку всего заявленного диапазона.

Вариативный шрифт может быть выходным форматом, но не заменяет выбранный
контракт смысловых частей и геометрических проверок. Поддержка такого
адаптера требует отдельной проверки, как описано в
[геометрических инвариантах](foundations.md).

Интерполяция контуров допускается после установления их соответствия.
Одной `topologySignature` недостаточно для доказательства корректности
прямого морфинга:
важны соответствие контуров, направление обхода, начальные точки и структура
контрольных точек. Неизвестное соответствие не угадывается молча.
