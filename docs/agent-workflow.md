# Как добавить иконку

Цель процесса — получить пару `Outline`/`Filled`, совместимую с библиотекой, не выдавая статический SVG за параметрическую или анимационную модель.

## Что является контрактом

- `iconDesignContract` из `@labpics/icons/ir` — машинная граница канвы, исходного SVG, осей и экспортных целей;
- `semantics/grid.json` — размеры, keylines, веса, просветы и допустимые направления;
- `docs/foundations.md` — правила оптики, отрицательного пространства и semantic parts;
- `glyphCapabilities(icon, variant)` — фактические возможности конкретного варианта.

Метрика не выбирает красивую форму. Она отбрасывает решения, которые нарушают измеримый инвариант. Силуэт, узнаваемость и характер проверяются визуально рядом с иконками того же архетипа.

## Рабочий маршрут

1. Сформулировать смысл иконки одним предложением и выбрать ближайшие семейства в каталоге.
2. Выбрать keyline по типу массы: круг, квадрат, широкая или высокая форма.
3. Нарисовать `Outline` и `Filled` как два самостоятельных мастера. Filled не получается механическим расширением Outline.
4. Экспортировать пару в `<export-dir>/{Outline,Filled}` и положить рядом
   `<export-dir>/proposal.json`. Proposal обязан явно назвать смысл, ближайшие
   семейства, keyline, связь мастеров, измеримые ограничения отрицательного пространства,
   поведение оптического размера, смысловые части и возможные жесты.
5. Проверить предложение без записи в репозиторий:

   ```powershell
   pnpm validate:proposal -- --source "<export-dir>" --icons icon-name --json
   ```

6. После визуального ревью импортировать пару:

   ```powershell
   pnpm import:figma -- --source "<export-dir>" --icons icon-name --write
   ```

7. Пересобрать каталог, открыть Observatory и пройти полную проверку:

   ```powershell
   pnpm build
   pnpm observatory
   pnpm verify
   ```

`validate:proposal` проверяет закрытый SVG-язык, строгую схему proposal,
существование family references, парность, канву/поля, fill-rule/topology,
keyline-контейнеры и доказуемый сдвиг идентичных контуров. Команда ничего не
записывает. `pnpm verify` остаётся единой полной проверкой.

иллюстративному предложению, не задают новые пороги системы. Перед импортом

## Границы приёмки

Модель, её оси и жесты принимаются раздельно. [Справка возможностей](capabilities.md)
объясняет, что означают эти уровни и почему авторский источник не получает
параметрические возможности автоматически. После изменения каталога проверьте
`glyphCapabilities()`; отсутствие поддержанной оси должно давать явный отказ.

Lottie и SF Symbols не входят в экспортируемую поверхность пакета. Идентификаторы
геометрических частей `source-only` стабильны для неизменного источника, но не
являются смысловыми именами. Новая ось, жест или морфинг требуют собственного
контракта и проверки, обнаруживающей его нарушение; общая трансформация всей
картинки не подменяет этот результат.

## Откат

До импорта сохраните исходные файлы и декларации в рабочей ветке и убедитесь,
что нет чужих незакоммиченных правок. Для возврата используйте сохранённый commit
только для затронутых путей, затем повторите `pnpm build && pnpm verify`.
Не восстанавливайте весь checkout поверх чужих изменений. Импорт не публикует
пакет и не меняет внешние системы; правила исправления опубликованного выпуска
описаны в [процедуре релиза](build-release.md#исправление-ошибки).
