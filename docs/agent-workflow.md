# Как добавить иконку

Подготовьте самостоятельные мастера `Outline` и `Filled`.
Силуэт, узнаваемость и характер сравнивайте с иконками того же семейства.

## Подготовка

Размеры, направляющие, веса и просветы заданы в
[геометрической сетке](../semantics/grid.json). [Основы](foundations.md) объясняют
оптику и отрицательное пространство. `iconDesignContract` из `@labpics/icons/ir`
содержит ограничения канвы, исходного SVG, осей и экспортных целей.
Доступные возможности варианта возвращает `glyphCapabilities(icon, variant)`.

## Рабочий маршрут

1. Сформулируйте смысл и выберите ближайшие семейства в каталоге.
2. Выберите направляющую по форме массы: круг, квадрат, широкий или высокий прямоугольник.
3. Нарисуйте каждый мастер отдельно, учитывая вес, просветы и оптическое равновесие.
4. Экспортируйте пару в `<export-dir>/{Outline,Filled}`. В соседнем `proposal.json`
   укажите смысл, семейства, направляющую, связь мастеров, измеренные просветы,
   поведение оптического размера, смысловые части и возможные жесты.
5. Проверьте предложение:

   ```powershell
   pnpm validate:proposal -- --source "<export-dir>" --icons icon-name --json
   ```

   Команда проверяет SVG, структуру предложения, ссылки на семейства, парность,
   канву, поля, правила заливки, топологию и размещение в направляющей.
   Она обнаруживает смещение идентичных контуров и ничего не записывает.

6. После визуального ревью импортируйте пару:

   ```powershell
   pnpm import:figma -- --source "<export-dir>" --icons icon-name --write
   ```

7. Пересоберите каталог и откройте Observatory для сравнения. Завершите проверкой:

   ```powershell
   pnpm build
   pnpm observatory
   pnpm verify
   ```

## Границы приёмки

Модель, оси и жесты принимаются раздельно по [правилам возможностей](capabilities.md).
После обновления каталога проверьте `glyphCapabilities()`. Запрос неподдержанной
оси должен завершаться явной ошибкой.

Экспорт в Lottie и SF Symbols отсутствует. Идентификаторы частей `source-only`
описывают геометрию и стабильны при неизменном исходнике. Смысловые части
определяются отдельно. Для новой оси проверяются её диапазон и поведение,
для жеста или морфинга проверяются траектория и топология.

## Откат

Перед импортом сохраните исходники и декларации в коммите рабочей ветки.
Убедитесь, что затронутые файлы свободны от чужих незакоммиченных изменений.
Для возврата восстановите только эти пути из сохранённого коммита и выполните
`pnpm build && pnpm verify`. Остальные файлы рабочей копии оставьте без изменений.

Импорт меняет только репозиторий. Публикация и исправление выпущенного пакета
описаны в [инструкции релиза](build-release.md#исправление-ошибки).
