# Обновить авторский корпус

Текущий корпус задаёт [SymbolSource](symbol-source.md): `symbols/source.json`
связывает семейства, неизменяемые masters, части и общие компоненты.
[Figma Lab UI](https://www.figma.com/design/LuaiBd4anRi4DMZayKAnY2) используется
строго для чтения. Эта процедура не изменяет файл Figma.

## Подготовка

Проверьте выбранное семейство в `symbols/source.json`: пару `outline`/`filled`,
`provenance`, `anatomy` и ссылки на `components`. Канва записана в `canvas`;
`axisDesign` содержит опоры осей. Поддержку определяют проверенные оптические
masters всего корпуса; незавершённые рецепты можно смотреть в optical atlas.
Возможности текущего варианта сообщает `glyphCapabilities(variant)` из его
модуля `@labpics/icons/symbols/<id>`; примеры есть в
[подключении символов](symbol-modules.md).

Полный `@labpics/icons/ir`, его `iconDesignContract` и старые модели относятся
к compatibility-снимку. Каталог `svg/` сохраняет неизменяемую геометрию этого
снимка. Команда `import:figma` работает с ним и не используется для обновления
авторского корпуса.

## Обновление существующих семейств

1. Сохраните полный read-only экспорт той же Figma и manifest снимка.
   Состав семейств должен совпадать с `symbols/source.json`; для каждого нужны
   Outline и Filled. `<export-root>` содержит файлы по относительным путям
   `master` из manifest. Формат receipt показан в
   [проекции авторского снимка](../semantics/figma-baseline.json): file/node/version,
   размер и SHA-256 исходных bytes, SHA-256 нормализованного SVG и fingerprint
   путей. Manifest формируется из фактического экспорта.
2. Проверьте снимок без записи:

   ```sh
   pnpm sync:figma --capture "<export-root>" --manifest "<receipt.json>"
   ```

   Команда проверяет весь снимок и сообщает изменённые masters. Неполный набор,
   другой Figma file или несовпадение receipt останавливают импорт.
3. Сравните изменённые Outline/Filled с прежними masters и соседними семействами:
   силуэт, узнаваемость, вес, просветы и оптическое равновесие. Если изменились
   части общей компоненты, согласуйте её декларацию в `symbols/source.json`
   и повторите проверку. Изменение SVG, участвующего в группе состояний,
   требует отдельной миграции корпуса с пересмотром группы: `sync:figma`
   останавливает такой импорт до записи даже при прежних контурах.
4. После визуального ревью примените проверенный снимок:

   ```sh
   pnpm sync:figma --capture "<export-root>" --manifest "<receipt.json>" --write
   ```

   Неизменившиеся masters сохраняют путь и версию. Изменённые записываются под
   новой версией; существующий master нельзя перезаписать. Изменение контуров
   сбрасывает прежнюю семантическую аннотацию в `unclassified`. Импорт обновляет
   источник и его производные проекции.
5. Соберите пакет и атлас текущих авторских форм:

   ```sh
   pnpm build
   node scripts/build-source-atlas.mjs
   ```

   Откройте `preview/source-atlas.html`: проверьте оба начертания при 16/24/48 px
   и в светлом и тёмном окружении. Проверьте импорт изменённого символа через
   `@labpics/icons/symbols/<id>` и его provenance. Завершите `pnpm verify`.

`pnpm observatory` сравнивает старую геометрию с compatibility-моделями;
приёмка текущего авторского корпуса выполняется по source atlas и публичному импорту.
Для CI действуют [общие правила публичной экосистемы Lab UI](https://github.com/Labpics-Team/labui/blob/main/CONTRIBUTING.md#проверить-изменение).

## Части и производные файлы

Смысловые части и общие компоненты редактируются в `symbols/source.json`.
Правила старых моделей находятся в `symbols[id].compatibilityModel`.
После изменения источника выполните `pnpm generate:source`, затем
`pnpm check:source`. Генерируемые JSON в `semantics/`, каталоги и файлы `dist/`
не служат местом ручного редактирования. Список проекций приведён в
[справке источника](symbol-source.md).

Модель, ось и жест требуют собственных проверок соответствия текущему master.
Неподдержанная возможность должна возвращать явный отказ; прежняя приёмка
compatibility-модели не подтверждает паритет новой авторской формы.
Поддержку экспорта проверяйте через соответствующий адаптер, например
[`lottieCapabilities(variant)`](lottie.md).

## Добавление, удаление и переименование семейства

`sync:figma` отклоняет изменение состава семейств. Такое изменение требует
отдельной явной миграции корпуса: самостоятельных Outline/Filled masters с
provenance, изменения `symbols/source.json`, ссылок на части и состояния,
перегенерации поверхности пакета и проверки потребителя. Класс выпуска
определите по [политике совместимости](semver-policy.md).
Правка `svg/` или частичный legacy-импорт не выполняют эту миграцию.

Для создания самостоятельного символа через DesignSpec используйте
[authoring-процедуру](authoring.md). Она не изменяет Figma и автоматически
не добавляет символ в авторский корпус.

## Откат

До применения снимка сохраните изменения рабочей ветки в коммите.
Для возврата восстановите прежний `symbols/source.json` и связанные изменения
этого импорта, затем выполните `pnpm generate:source` и `pnpm verify`.
Сохранённые masters позволяют снова сослаться на прежнюю версию без изменения
её bytes. Чужие изменения рабочей копии сохраняются.

Публикация и исправление выпущенного пакета описаны в
[инструкции релиза](build-release.md#исправление-ошибки).
