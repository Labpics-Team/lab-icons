# Источник символа

`symbols/source.json` — редактируемый источник семейств. Ключ семейства связывает
Outline/Filled по provenance Figma. Наличие `fill` в SVG не определяет начертание:
оба варианта состоят из заполненных контуров.

Координаты находятся в неизменяемых SVG masters. `anatomy.parts` хранит селекторы
путей/контуров, paint-порядок и семантическую роль. `unclassified` честно означает,
что смысл частей ещё не задан. `semantic` описывает части без старого runtime law;
`declared` дополнительно воспроизводит существующий compatibility-контракт.

`components.circle-outline` ссылается на авторский контур и общий anchor. Plus,
minus, checkmark и mic в круге используют эту часть; сборка проверяет точное
совпадение path и fill-rule. Внутренний знак сохраняет собственные координаты.
Filled с отрицательным знаком хранит counter-контуры, а не независимые залитые слои.
Микрофон сохраняет свою форму и отдельное сужение capsule.

`axisDesign` задаёт три опоры каждой оси; средняя опора — исходный рисунок.
Минимум, максимум и значение по умолчанию выводятся из этих массивов.
`opticalMaster` связывает семейство с `symbols/optics/<id>.json`. Простые формы
используют анатомические рецепты: размеры ссылаются на сегменты master,
а вес, просвет и оптическая поправка задаются явно. Общая оптика circle-outline
находится в `components.circle-outline.opticalRecipe`.

Компилятор проверяет все девять masters, команды, paint и winding контуров,
сохраняет среднюю опору и выводит разреженные коэффициенты четырёх билинейных
участков. Отсутствующие мастера и незавершённое визуальное ревью запрещают
полную оптическую сборку. Принятие `review: accepted` связывается через
`reviewedSha256` с точной компилированной геометрией. Изменение общего профиля
или рецепта требует повторного просмотра затронутых форм.

У каждой опоры могут быть независимые авторские `corrections` поверх общего
рецепта: `{weight, opsz, paths: [{pathIndex, delta: [coordinateIndex, change, ...]}]}`.
Координаты перечисляются в порядке M/L/C/Z исходного пути: x/y начала и линий,
x1/y1/x2/y2/x/y кубической кривой. Разреженная поправка относится только к указанной
опоре; угловая поправка становится самостоятельным mixed term. Среднюю опору
400/24 менять нельзя. `masterSha256` связывает индексы с точными исходными bytes.
`--regenerate` сохраняет поправки и выбранные рецепты; при смене source SHA
отказывает до любой записи, пока автор не перенесёт координатные связи.

`node scripts/draft-optical-corpus.mjs` создаёт недостающие совместимые черновики.
Они хранят поле смещения исходных контрольных точек, профиль и геометрическую
диагностику. Роль внешнего контура/отверстия определяется по фактическому fill-rule.
Тонкие детали ограничивают смещение локально, не ослабляя остальную форму.
Близкие управляющие точки получают согласованные смещения: короткий исходный
отрезок не должен разворачиваться из-за резкого изменения нормали. Для распознанных
осевых эллипсов поле меняет радиусы, сохраняя касательные и исходные микросегменты.
Близкие контуры одной paint-операции также согласуют смещения для сохранения
просветов и совпадающих границ. Микроскопические экспортные фрагменты следуют
окружающему полю переносом, сохраняя внутреннюю форму; их наличие не ослабляет
вес остальных частей символа.
Обе операции относятся к подготовке черновика и не заменяют его принятия.
Общие компоненты применяются поверх поля, поэтому общий круг сохраняет единый
рецепт. `--regenerate` обновляет только черновики этого генератора; авторские
рецепты не перезаписываются. Нормали округляются до шести знаков; исходные
координаты средней опоры не округляются.

Offset здесь служит материалом для доводки. Пересечения, ограниченные стыки
и неоднозначные границы остаются отмеченными; отсутствие предупреждений не
означает визуального принятия. Число пересечений сравнивается с исходником
на каждой опоре. Между опорами диагностируется сетка с серединой каждого интервала
через настоящий runtime sampler; конечная выборка не доказывает отсутствие
пересечений во всей непрерывной области осей.
[Paper.js](https://paperjs.org/reference/path/) используется только offline.

`node scripts/build-optical-atlas.mjs` создаёт постраничный атлас всего доступного
корпуса в `preview/optical-atlas/index.html`: обе темы, все опоры, исходник,
Geist и обычные/выбранные/icon-only кнопки. Снимки реального Chrome получаются
командой `node scripts/capture-optical-atlas.mjs --chrome`; без флага используется
Chromium Playwright. Manifest связывает страницы с семействами, отчёт подтверждает
наличие всех SVG и шрифта, отсутствие горизонтального переполнения.

`pnpm generate:source` выводит `semantics/figma-baseline.json`,
`semantics/author-anatomy.json`, `semantics/author-state-groups.json` и
`semantics/anatomy.json`. Их не редактируют вручную.
`pnpm check:source` обнаруживает расхождение. Census и каталоги продолжают
генерироваться сборкой; старые модели хранятся внутри семейства как
`compatibilityModel`, чтобы не терять подтверждённые эксперименты прежнего IR.

## Статическое подключение

```js
import { plusCircleOutline } from '@labpics/icons';
import plusCircle, { outline } from '@labpics/icons/symbols/plus-circle';

console.log(plusCircle.id, outline === plusCircleOutline);
```

Именованный импорт SVG оставляет в bundle только строку. `symbol` и default export
дают `{id, outline, filled, data}`, где `data` содержит совместимую сетку обеих
осей только этого семейства. Прежние `glyph`,
`glyphCapabilities`, states, variations и gestures сохраняются для существующего
LabUI consumer. Они выводятся из того же источника. Полный `/ir` отдельно использует
private `legacy-static.js`; его геометрия не подменяет обычный SVG.

```js
import plusCircle from '@labpics/icons/symbols/plus-circle';
import { renderIcon } from '@labpics/icons/render';

const svg = renderIcon(plusCircle, { size: 20, weight: 500, opsz: 'auto' });
```

Размер задаётся в CSS px. Автоматический `opsz` следует размеру и ограничивается
16…48; явный `opsz` независим от размера. Выход weight/opsz за объявленные границы
вызывает `RangeError`. Начертание по умолчанию — Outline. При 400/24 и размере 24
renderer возвращает точную исходную SVG-строку; прочие положения используют
числовые коэффициенты без SVG parser, DOM, observer или часов.

Обычная сборка требует визуально принятых masters всего корпуса. Для их доводки
`pnpm build:static` и `node scripts/build-ir.mjs --preview` создают явно черновой
артефакт. `node scripts/verify-optical-consumer.mjs --preview --chrome` упаковывает
этот артефакт, устанавливает в отдельный consumer, проверяет весь корпус и типы,
снимает реальный рендер Chrome и отсутствие сторонних семейств в одном импорте.
Preview не является разрешением публикации; production `prepack` повторяет чистую
сборку с обязательным `reviewedSha256`.

`loadAuthorBaseline(...).icons[id][variant].rawSvg` в offline authoring возвращает
точные исходные bytes. Статика меняет только разрешённую обвязку экспорта и цвет на
`currentColor`, сохраняя path, winding и fill-rule.

## Обновление экспорта Figma

Figma `LuaiBd4anRi4DMZayKAnY2` строго только читается. Сначала сохраняют полный
экспорт того же набора семейств и manifest с file/node/version,
SHA-256 исходного SVG, нормализованного SVG и fingerprint путей.

```sh
pnpm sync:figma --capture <export-root> --manifest <receipt.json>
pnpm sync:figma --capture <export-root> --manifest <receipt.json> --write
```

Проверка читает весь снимок до записи. Неизменившиеся masters сохраняют прежний путь
и версию; изменённые пишутся под новой версией. Перезапись старого master запрещена.
Изменение геометрии снимает прежнюю семантическую аннотацию. Изменённые общие части
требуют согласования в исходнике; импорт отказывает до записи при нарушении ссылок.
Любое изменение SVG, участвующего в группе состояний, требует отдельной миграции
с пересмотром группы и не принимается через `sync:figma`. Изменение состава публичных семейств
выполняется отдельной явной миграцией. Каталог `svg/` — неизменяемый
compatibility-снимок; legacy-команда `import:figma` не обновляет этот источник.
Изменение master семейства с оптическими рецептами также требует пересмотра
привязок до импорта: прежние ссылки на координаты нельзя переносить автоматически.
Полный порядок работы приведён в [процедуре обновления корпуса](agent-workflow.md).

`capture.source.version` обозначает текущий снимок всего корпуса.
`variants[variant].provenance.version` закрепляет исходную версию отдельного
неизменяемого master; при отсутствии этого поля используется версия снимка.
Декларации анатомии и групп состояний относятся к текущему снимку, а каждый
участник сохраняет file identity, версию master и точные хэши геометрии.
Новая версия снимка с прежними bytes не требует копирования masters или
повторного объявления частей. Так локальный источник различает
[версию файла Figma](https://developers.figma.com/docs/rest-api/file-endpoints/)
и версию сохранённого экспорта каждого символа.

## Проверенный срез

На 2026-11-16 сохранённый корпус содержит 330 семейств и 660 вариантов.
[Прямая сверка live Figma](evidence/figma-20261116/live-comparison.json) подтверждает
неизменность компонентов между сохранённой и актуальной версиями при одинаковых
REST-параметрах. Исторические node hashes получены с другими параметрами ответа;
они не сравниваются между схемами.

Это CORPUS-01: источник, provenance, статический корпус, общая анатомия и
совместимость. `axisDesign` хранит выбранные опоры weight/opsz;
на 2026-11-17 полный корпус получил совместимые оптические черновики.
Публичный `/render` и данные символов проверены через отдельно установленный
черновой артефакт. Доводка и визуальное принятие корпуса, семантическое движение,
полная проверка экспортов и публикация 0.4.0 остаются следующими узлами плана.

Принципы: [Node.js subpath exports](https://nodejs.org/api/packages.html#subpath-patterns),
[Apple: общие части и анимация символов](https://developer.apple.com/videos/play/wwdc2023/10257/).
