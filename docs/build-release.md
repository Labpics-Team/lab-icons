# Как собрать и выпустить пакет

Работайте в отдельной ветке с полной Git-историей: геометрические проверки
сравнивают результат с сохранёнными авторскими версиями. Требования к инструментам
находятся в [справке пакета](package.md#среда-разработки).

## Проверка изменения

```sh
pnpm install --frozen-lockfile
pnpm verify
```

`pnpm verify` проверяет сборку, геометрию, декларации, состав и размер пакета,
затем запускает тесты. Список команд находится в [package.json](../package.json).

Для визуального сравнения выполните:

```sh
pnpm observatory
```

Откройте `preview/observatory.html` и сравните исходник с моделью, наложением
контуров и измерениями. Решение о приёмке варианта принимается после визуального ревью.

## Сборка и упаковка

```sh
pnpm build
pnpm pack
```

Сборка создаёт статические экспорты, каталог и Glyph IR. Упаковка повторяет
её через `prepack`. Состав пакета задан в [контракте поставки](../release/contract.json).

`pnpm check:package-artifact` устанавливает пакет из чистой сборки в отдельный
тестовый проект. Проверяются ESM-импорты, декларации типов и отказ CommonJS-входов.
Проверка размера охватывает каждый файл контракта.

## Обновление справки

После изменения метаданных или контракта поставки выполните:

```sh
node scripts/check-docs-drift.js --write
node scripts/check-docs-drift.js --check
```

`--write` обновляет `docs/package.md`. `--check` сообщает об отсутствующей или
устаревшей справке без записи в файлы. Генерация останавливается при ошибке
исходного контракта. Переводы строк CRLF допустимы.

Проверка также находит известные противоречия каналу установки в README и
вложенных документах. После генерации просмотрите diff и пояснения к изменённым полям.

## Релиз

Выберите коммит после успешных обязательных проверок и ревью.
Версию определите по [политике совместимости](semver-policy.md).
Тег исходников должен совпадать с `v<package.json#version>`.

В Bash из корня проверенной рабочей копии:

```sh
set -euo pipefail
source_commit=$(git rev-parse --verify 'HEAD^{commit}')
version=$(git show "$source_commit:package.json" | node --input-type=module -e 'import { readFileSync } from "node:fs"; console.log(JSON.parse(readFileSync(0, "utf8")).version)')
git tag "v$version" "$source_commit"
git push origin "refs/tags/v$version"
```

Версия читается из выбранного коммита; незакоммиченные изменения остаются
в рабочей копии. При ошибке команда останавливается. Если push завершился
неудачно, проверьте состояние удалённого тега перед повтором.

[Workflow релиза](../.github/workflows/release-dist.yml) проверяет исходный тег
и создаёт тег собранного пакета. Повтор допускается после сверки происхождения
и байтов с чистой сборкой. Опубликованные теги сохраняют положение и содержимое;
принудительное обновление запрещено.

Наличие конкретной версии в npm проверьте в реестре отдельно.

## Исправление ошибки

До публикации исправьте PR и повторите проверки. Для опубликованного пакета
подготовьте новую версию. Содержимое прежней версии сохраняется, а потребители
переходят на исправление при обновлении зависимости.
