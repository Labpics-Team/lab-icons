# Жизненный цикл иконки — ADR (r2 DOC-01)

## Решение: три ортогональные оси вместо одной лестницы

Судьба иконки описывается тремя независимыми полями, не одним статусом:

| Ось | Значения | Владелец истины |
|---|---|---|
| `representation` | `source` → `transcript` → `semantic` | как выражена геометрия |
| `acceptance` | `candidate` → `accepted` / `rejected` | production-пригодность решения |
| `capabilities` | оси weight/corner/opsz, части, жесты | что доказано исполняемым proof |

Смешение осей — источник инцидента августа 2026: 163 lossless
arc-chain-транскрипции подняли счётчик «modeled» 75→238 без единой новой
способности, при этом полный verify был красным (9 падений), а публичный
IR-бандл вырос с 947 КБ до 4.53 МБ. Транскрипция — форма записи, не
семантика и не приёмка.

## Инварианты

- **Transcript ≠ capability.** Транскрипция руки (fit IoU ≥ порога из
  `semantics/quality-thresholds.json`) не даёт частей, осей, жестов и не
  входит в default public bundle. Это офлайн-форма для анализа и миграции.
- **Acceptance не выводится из representation.** Source-only иконка может
  быть accepted (рука — законная поставка); semantic-модель может быть
  candidate (закон не подтверждён оптическим proof).
- **Capability только через исполняемый proof.** Ось публикуется после
  axis-proof (min/interior/default/max, топология, растровые фазы); жест —
  после trajectory/topology proof. Наличие файла или поля не повышает этап
  (см. Capability boundary в `anatomy-model.md`).

## Отклонённые альтернативы

- **Одна лестница `source→modeled→accepted`** (r1): заставляет транскрипцию
  маскироваться под модель ради движения счётчика — доказанный вред.
- **Append-only decision ledger** (event sourcing поверх git): второй SSOT
  и недоказанная машинерия; git-история и immutable-теги уже дают аудит.

## Порог качества — один источник

Все пороги (transcript fit, generated drift/fidelity, auto-acceptance) живут
в `semantics/quality-thresholds.json`; гейты импортируют значения оттуда.
Правка порога — версионируемое решение с обоснованием в коммите, не правка
константы в глубине скрипта.

## Вход новой иконки (в т.ч. нарисованной ИИ)

1. Proposal с версией формата; отказ — закрытый enum причин (fail-closed).
2. Легальный вход — `source-only`: рука/ИИ-рисунок сразу поставляется как
   точный SVG после гейтов корпуса.
3. Транскрипция и semantic-модель — асинхронный долг, не блокирует поставку.
4. Приёмка и способности двигаются только доказательствами, каждая по
   своей оси.
