# Система `system/` — канон конструкции иконки из токенов

Роль: канон. Этот документ — контракт. Всё, что ниже, обязательно к исполнению для любого,
кто добавляет глиф: человека или агента.

## Зачем система

Иконка в библиотеке — не рисунок, а **декларация**: закон словами плюс
построитель из токенов. Файл `.svg` производен и воспроизводим. Цель — чтобы
новый глиф нельзя было нарисовать «на глаз»: у автора просто нет места, куда
вписать выдуманное число.

## Законы, которые уже выведены (не переоткрывать)

* Канва 24, поле 1, живая область 22. Keyline-окружность d = 22.
* Перо: base 1.8 (Regular), bold 2.4 (Filled того же штриха), кольцо-обрамление
  1.5, глиф-в-контейнере 2.0, волосяное 1.2.
* **Терминал = полукруг радиусом перо/2.** Не токен — вывод.
* **Внутренняя кромка = внешняя − перо.** Не токен — вывод.
* **Скруглённый квадрат вписан углами в keyline-окружность:**
  `h = R + (Rkey − R)/√2`. При R = 5: габарит 18.485; рука нарисовала 18.48.
* **Осевой терминальный keyline = 6**: терминалы minus, plus и close стоят
  ровно на нём (6.00 / 6.06 / 6.01 — три независимых замера).
* **Сглаживание ζ = 0.6** воспроизводит скруглённый квадрат Filled с
  отклонением 0.05%. Радиус вершины при этом не меняется — сокращается дуга,
  а вход в неё берёт кубика с нулевой кривизной у прямой (G2).
* **Локоть шеврона** — негативное пространство: внутренняя кромка V касается
  окружности радиуса `clearance.channel` в центре канвы. Отсюда вершина.
* **Луч солнца**: внешний терминал закреплён на `Rkey − кап`; длина — ось от 0
  (sun-low) до `Rkey − кап − Rтела − зазор − кап`.
* **Бейдж**: диск вписан в верхний правый угол живой области —
  центр `(canvas − margin − r, margin + r)`.
* **Перечёркивание**: ось от `(canvas−margin−cap, margin+cap)` до
  `(margin+cap, canvas−margin−cap)` — терминалы упираются в углы живой области.

## Как измеряется сходимость

Две метрики, обе обязательны.

1. **Отклонение площади** `1 − IoU` по чернилам на растре 384². Это то, что
   просил владелец, и оно в превью первой колонкой.
2. **Смещение контура** — медиана и p95 расстояния от контура генерата до
   контура оригинала, в единицах канвы и в долях пера.

Вторая метрика нужна, потому что первая на штриховых глифах нелинейно жестока:
для двух штрихов пера `w`, разошедшихся на `δ` по нормали,

```
1 − IoU ≈ 2δ / (2w − δ)
```

При `w = 1.8` смещение **0.027 ед.** (1/890 канвы) уже даёт 3%. Собственный
разброс руки внутри одного глифа больше: у `chevron-down` два терминала ОДНОГО
штриха стоят на 0.063 друг от друга, плечи идут под 44.75° вместо 45°. То есть
на штрихах площадной порог 3% меряет дребезг оригинала, а не расхождение
конструкции. Поэтому вердикт `registration` (медиана смещения ≤ 0.06 ед.)
считается сходимостью независимо от процента площади — и превью обязано это
проговорить текстом.

## Смотреть глазами — обязательный шаг, не роскошь

Процент — интеграл, и он врёт в обе стороны. Глиф может набрать 2% и быть
перевёрнутым по fill-rule в тонком месте, разорванным в одном узле или
зеркальным: площадь такое иногда не ловит вовсе, а глаз ловит мгновенно.
Обратное тоже верно — 16% у `dice/filled` оказались не поломкой формы, а тем,
что рука отвела фишки от шва на 1.4; увидеть это в числе было нельзя.

```bash
node system/contact-sheet.mjs            # system/out/contact-outline.png
node system/contact-sheet.mjs --filled
node system/contact-sheet.mjs --only music,dice --cols 4
```

Лист рисует наложение: оригинал серым, генерат синим поверх. Ровный синий
силуэт — совпало. Серая кайма — смещение. Серая деталь — не построена.
**Сдавать семью, не посмотрев на её лист, нельзя.**

## Правила декларации глифа

```js
import { defineGlyph } from '../registry.js';

defineGlyph('имя', {
  family: 'семья',
  law: 'закон словами: из чего построено и почему числа именно такие',
  argument: 'текст в превью, если отклонение > 3% (необязателен иначе)',
  axes: { имя: { min, def, max, unit, note } },   // локальные оси
  outline: (t, ax) => Path,
  filled:  (t, ax) => Path,   // если Filled не сводится к Bold-перу
});
```

Жёсткие требования:

1. **`law` обязателен.** Декларация без закона не принимается реестром.
2. **Перо — `t.stroke.glyph`, не `t.stroke.base`.** Иначе глиф теряет ось `fill`
   (Filled штрихового знака — это его же Bold-начертание).
3. **Ни одного числа без происхождения.** Число либо выводится из токенов,
   либо объявлено семейным токеном с указанием замера по корпусу
   (`export const X = …` + комментарий с числами замеров).
4. **Никаких `evenodd`.** Дырки возвращаются развёрнутыми, система живёт на
   `nonzero`. Это структурно исключает класс дефектов «контур залился блобом».
5. **Переиспользовать части.** Если форма похожа на уже объявленную — она ею
   и является с другим параметром. `arrow` = `chevron` + хвост; `close` = `plus`,
   повёрнутый на 45°; `sun-low` = `sun` при `ray = 0`.
6. **Накладной класс сначала вырезает свою тень.** `withSlash`, `withBadge` —
   негативное пространство строится, а не проверяется.

## Дуктус — с чего начинать разбор глифа

**Не выбирай модель глазами. Замерь.** Максимальная окружность, вписанная в
чернила, — это ровно то перо, которым в этой точке вели. Отсюда:

* радиус ≈ const по длине ⟹ ШТРИХ, и 2r даёт перо;
* радиус скачком больше ⟹ МАССА (голова ноты, диск солнца);
* конец цепочки центров ⟹ ТЕРМИНАЛ, его радиус обязан равняться перу/2;
* максимальная окружность в СЧЁТЧИКЕ ⟹ негативное пространство, измеренное;
* минимальная ОПИСАННАЯ окружность ⟹ фактический keyline глифа;
* число связных кусков чернил ⟹ РАЗРЫВЫ, которых на глаз не видно.

```bash
node system/ductus.js signature      # 4 куска чернил, перо 1.8 (94%), keyline 11.0
node system/ductus.js dice           # 8 кусков: корпус и 7 фишек; грани — счётчики
```

Что это даёт на практике: у `dice` подгон при включённом ζ сошёлся к скруглению
**3.926**, а в `d` оригинала стоит `a3.9 3.9`. Без сглаживания оптимум уезжает
на 3.2. То есть дуктус не «подтвердил догадку», а показал, что рука вела углы
сглаженными.

Сверка дуктусов оригинала и генерата ловит то, что площадная метрика не видит
в принципе — потерянную деталь, слипшийся просвет, не тот калибр:

```bash
node system/check-family.mjs system/glyphs/<семья>.js --ductus
node system/check-system.js --ductus
```

## Инструмент подгона

`system/fit.js` отвечает на вопрос «какие числа рука имела в виду». Порядок:
подогнать → увидеть закон → подставить закон → измерить цену подстановки.
Подогнанные числа в декларацию НЕ попадают; попадает закон.

```js
import { fitToMask } from '../fit.js';
import { maskFromSvg } from '../metrics.js';
const ref = maskFromSvg(readFileSync('reference/Outline/имя.svg','utf8'), 24, 8);
const f = fitToMask(ref, (p) => построитель(p), [нач], [шаг], { iters: 1200 });
```

## Подготовка к анимации

Анимации здесь не делаются, но данные для них не теряются. Модель пути хранит
дугу центром и углами, поэтому ось вращения кругового штриха (вокруг которой
крутится reload, вокруг своей — earth) лежит в данных, а не восстанавливается
обратной задачей из эндпоинтов. `system/motion.js` её просто достаёт:

* `pivots` — центры дуг с суммарным заметённым углом и радиусами, ранжированные
  как `угол × радиус`: терминал пера тоже заметает 180°, но радиус у него 0.9,
  и кольцу радиуса 11 он честно уступает;
* `spans` — прямые звенья с направлением и длиной (кандидаты на draw);
* `ink` — габарит и центроид чернил (якорь масштабирования).

Автору глифа декларировать нечего: если он построил кольцо кольцом, ось
найдётся сама. Второй канал — оси вариативности: то, что будет двигаться
(длина луча, длина хвоста, вес), уже параметризовано.

## Оригиналы

`reference/` — замороженные рисунки руки, извлечённые из первого коммита
каждого файла. Они **неприкосновенны**: это точка отсчёта сходимости. Ничего,
кроме чтения, с ними делать нельзя.
